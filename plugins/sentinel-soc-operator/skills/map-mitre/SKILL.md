# Map MITRE ATT&CK

## Purpose

Classify alerts, incidents, hunting findings, or investigation events by MITRE ATT&CK tactic and technique. This skill uses a 3-layer mapping approach: alert name pattern matching, analytics rule metadata lookup, and raw event heuristics. All references use official MITRE ATT&CK tactic IDs (TAxxxx) and technique IDs (Txxxx or Txxxx.xxx).

## When to Use

- After incident summarization to classify the threat by ATT&CK tactics
- During investigation to map timeline events to techniques
- After threat hunting to categorize findings
- When building detection rules to assign MITRE coverage
- For MITRE ATT&CK coverage gap analysis across analytics rules

## Instructions

1. **Receive input**: Accept one of:
   - Alert data from an incident (alert names, descriptions, properties)
   - Investigation findings (event data, timeline entries)
   - Hunting results (KQL query output with event details)
   - Coverage analysis request (no input -- analyze all active rules)

2. **Layer 1 -- Alert name pattern matching**: For each alert, match the alert name against known tactic keywords:
   - "Initial Access" or "Phishing" -> TA0001 (Initial Access)
   - "Execution" or "PowerShell" or "Script" -> TA0002 (Execution)
   - "Persistence" or "Scheduled Task" or "Registry" -> TA0003 (Persistence)
   - "Privilege Escalation" -> TA0004 (Privilege Escalation)
   - "Defense Evasion" or "Obfuscation" -> TA0005 (Defense Evasion)
   - "Credential Access" or "Credential" or "Brute Force" -> TA0006 (Credential Access)
   - "Discovery" or "Reconnaissance" -> TA0007 (Discovery)
   - "Lateral Movement" or "RDP" or "Remote" -> TA0008 (Lateral Movement)
   - "Collection" or "Data Staging" -> TA0009 (Collection)
   - "Exfiltration" or "Data Transfer" -> TA0010 (Exfiltration)
   - "Command and Control" or "C2" or "Beacon" -> TA0011 (Command and Control)
   - "Impact" or "Ransomware" or "Wiper" -> TA0040 (Impact)
   - Record confidence as "Medium" for pattern-based matches.

3. **Layer 2 -- Analytics rule metadata**: For each alert that was generated by a Sentinel analytics rule, call `sentinel_get_analytics_rule` with the rule ID (extracted from the alert's `AlertProviderName` or extended properties). Extract the Tactics and Techniques arrays from the rule definition. Record confidence as "High" for rule-defined mappings (these are authoritative).

4. **Layer 3 -- Raw event heuristics**: For investigation or hunting findings not linked to analytics rules, apply event-based heuristics:
   - EventID 4688 (Process Creation) + `powershell.exe` or `cmd.exe` -> T1059.001 (PowerShell) or T1059.003 (Windows Command Shell)
   - EventID 4624 Type 10 (Remote Interactive) -> T1021.001 (Remote Desktop Protocol)
   - EventID 4698 (Scheduled Task Created) -> T1053.005 (Scheduled Task/Job)
   - EventID 4672 (Special Privileges) -> T1078 (Valid Accounts)
   - DNS query to known DGA pattern -> T1568.002 (Domain Generation Algorithms)
   - Outbound connection to unusual port -> T1571 (Non-Standard Port)
   - Record confidence as "Low" for heuristic matches.

5. **Compile MITRE mapping table**: Aggregate all mappings into a single table sorted by tactic phase (kill chain order). Include tactic ID, tactic name, technique ID, technique name, confidence level, mapping source (Layer 1/2/3), and source evidence (alert name, rule ID, or event details).

6. **For coverage analysis**: If requested, call `sentinel_list_analytics_rules` to get all active rules. Extract MITRE mappings from each rule. Produce a coverage matrix showing:
   - Tactics with coverage (rules mapped)
   - Tactics without coverage (gaps)
   - Technique-level detail for covered tactics

## Expected MCP Tools

- `sentinel_get_incident_alerts` -- Get alert data for pattern matching (Layer 1)
- `sentinel_get_analytics_rule` -- Get rule MITRE metadata (Layer 2)
- `sentinel_list_analytics_rules` -- List all rules for coverage analysis

## Input

One of:
- **Alert data**: List of alerts with names, descriptions, and rule references
- **Event data**: Investigation or hunting results with event fields
- **Coverage request**: Keyword "coverage" or "gap analysis" to trigger full rule scan
